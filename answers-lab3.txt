Exercise 4:
1. What is the purpose of having an individual handler 
function for each exception/interrupt? (i.e., if all 
exceptions/interrupts were delivered to the same handler, 
what feature that exists in the current implementation 
could not be provided?)
ANSWER: Having individual handler functions for each exception/interrupt
is crucial because they allow for distinguishing between different types of
traps (i.e. those that have error codes and those that do not), as well as
determining the correct trap number via the individual handler.

2. Did you have to do anything to make the user/softint 
program behave correctly? The grade script expects it to 
produce a general protection fault (trap 13), but softint’s 
code says int $14. Why should this produce interrupt vector 
13? What happens if the kernel actually allows softint’s 
int $14 instruction to invoke the kernel’s page fault handler 
(which is interrupt vector 14)?
ANSWER: Nothing needed to be changed to make the user/softint program behave
correctly. The interrupt vector 13 was produced because int $14 does not allow
for user programs to access the page fault handler, instead directing iv13 to be
triggered. If this was allowed, then this would potentially be a security issue
that would allow a user to access kernel-level information/privileges.
